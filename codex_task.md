Задача безопасности [HIGH] — Parser SSRF/Chromium egress gap.

Файлы: src/security/external-url.ts, src/adapter-1688.ts

Проблема: внешний URL валидируется один раз в external-url.ts, затем
adapter-1688.ts вызывает route.continue(), и Chromium резолвит DNS заново —
между проверкой и реальным TCP-соединением возможен DNS rebinding /
TOCTOU-бypass приватных адресов.

Задача:
1. Изучи текущую логику проверки (resolve + validate) и то, как
   route.continue() передаёт управление Chromium.
2. Реализуй схему "resolve once -> validate -> pin connection": либо через
   CDP/network interception, которая привязывает уже провалидированный IP
   к фактическому сокету, либо через egress-прокси с DNS pinning. Не ломай
   существующий функционал парсинга маркетплейсов.
3. Добавь тесты: redirect на приватный адрес, DNS rebinding сценарий,
   IPv4-mapped IPv6, метаданные-эндпоинты (169.254.169.254 и аналоги).
4. Прогони весь существующий test suite и typecheck, ничего не должно
   сломаться.
5. Не трогай сетевую конфигурацию вне репозитория, не угадывай production
   топологию.
6. В конце — summary: что изменено, какие тесты добавлены/прогнаны, что
   осталось не проверено (например, поведение в реальной проде).

Работай только в этом репозитории. Коммить изменения локально с понятным
сообщением, не пушь.
